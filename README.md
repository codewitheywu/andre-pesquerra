# Andre V. Pesquerra — Portfolio

Personal portfolio built with Next.js 16 (App Router), TypeScript, Tailwind CSS v4 and Supabase.

## Getting started

```bash
npm install
cp .env.example .env.local   # then fill in your Supabase values
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Supabase is optional: without it the site renders
the fallback content in `src/data/content.ts`. Environment variables are validated at startup
(`src/lib/env.ts`); a half-configured Supabase pair fails fast.

## Consulting inquiries

The form on `/consulting` stores inquiries in `contact_messages` through a Server Action:

1. Apply `supabase/migrations/004_consulting_inquiries.sql` (adds the inquiry columns and
   `public.submit_inquiry`, executable only by `service_role`).
2. Set `SUPABASE_SECRET_KEY` (Supabase → Project Settings → API Keys → secret key) in
   `.env.local` and in the Vercel project's environment variables. Never prefix it with
   `NEXT_PUBLIC_`. Without it the form stays up but says sending failed and offers email.

Each visitor can send 3 inquiries an hour; the 4th gets the form's 429 panel. Visitors are
counted by an HMAC of their IP keyed with the secret, so no address is stored. Read inquiries in
the Supabase table editor (`contact_messages`, newest first).

## Project structure

```
src/
  app/
    (site)/            Public routes: shell (sidebar, mobile bar, palette), homepage, /stack, /blog, /behind-the-code, /recommendations, /consulting (+ inquiry Server Action), error boundary
    layout.tsx         Root layout: fonts, metadata, smooth scroll
    not-found.tsx      Styled 404
    robots.ts, sitemap.ts, icon.svg
  assets/              Statically imported images (blur placeholders)
  components/
    layout/            Sidebar, mobile bar, footer, command palette (⌘K), theme and sound toggles
    sections/          Hero, Projects, Experience (+ tools logo row), GitHubActivity, Certifications, Recommendations, Contact
    ui/                Primitives: Section, TextLink, LinkList, Kbd, CopyButton, Reveal, Marquee, icons
  data/content.ts      Static content (incl. certifications) and database fallbacks
  data/stack.ts        Every tool on /stack, by category; those with logos feed the logo row
  data/blog.ts         TikTok posts listed on /blog (linked out, not embedded)
  data/behind.ts       Story, life and hobbies for /behind-the-code (sections hide until filled)
  data/consulting.ts   Services, budget ranges and field limits for /consulting
  hooks/               useHydrated, useTheme / useSoundEnabled
  lib/
    env.ts             Zod-validated environment (env.server.ts: server-only secrets)
    inquiry.ts         Inquiry form validation (zod), shared by the Server Action and tests
    queries.ts         Server-side data access
    mappers.ts         Row validation and mapping (unit tested)
    motion.ts          Shared animation timing
    theme.ts, sound.ts Visitor preferences (iced/hot coffee theme, optional sound effects)
    github.ts          Public contribution calendar (cached 1h; falls back to a link)
    supabase/          The only place Supabase clients are created
  styles/globals.css   Light-coffee tokens and the Tailwind v4 design system
  types/               UI types; database.ts is generated (see below)
public/halftone.svg    Coffee-ring texture, generated by scripts/halftone.mjs (node scripts/halftone.mjs)
supabase/
  migrations/          Every schema change, applied in order
  seed.sql             Local development data
tests/
  unit/                Vitest
  e2e/                 Playwright (+ axe accessibility scans)
```

## Database types

`src/types/database.ts` must be generated, never hand-written:

```bash
npx supabase login
npx supabase link --project-ref <your-project-ref>
npm run db:types
```

Until then, every row is validated at runtime by the zod schemas in `src/lib/mappers.ts`.
