Overview

🌱 Foundation & Planning
My Capstone/Thesis project: a full-stack Dental Clinic Management System for Gavina Noble Dental Clinic, built to digitize scheduling, records, billing, and inventory. I designed the 19-table MySQL schema and architecture, then built it with the team in PHP + PDO + MySQL with a responsive blue/green UI.

👥 Leading the Team
I led a team of 4 developers on this build — setting the architecture and data model, dividing up the modules, reviewing every pull, and making the final calls on structure and conventions. The same discipline I've carried into every team project since: decide the standards up front, then hold the team to them in review.

🏗️ What I Built
Patients get a landing page, multi-step registration, a login portal for appointments and treatment history, and a PWA/APK install option. Three role-based dashboards — Admin, Doctor, Receptionist — each with their own permissions. Appointments support scheduling, rescheduling, auto-decline after a set window, and status notifications. Clinical modules cover treatment plans, medical records, and services pricing; inventory tracks stock levels and low-stock alerts. Reports run on Chart.js with PDF/Excel export via jsPDF and SheetJS, plus an in-app live chat widget.

🚀 Deployment
Hosted on Hostinger at gavinadental.online with clean URL routing via .htaccess, and packaged as an Android APK via a WebView wrapper — fully live for real users.

🏆 The Result
The system earned the Best in Project Implementation award at my thesis defense at Mondriaan Aura College — the centerpiece of my portfolio.

Challenges

Designing a 19-table relational schema covering patients, appointments, treatments, inventory, and staff without breaking relationships took real care — and directing 4 developers against that schema meant defining conventions early so everyone's modules fit together without conflicts. Role-based access control for three user types meant auditing every route and action so no one could reach what they shouldn't. Getting the appointment auto-decline logic and real-time notifications to fire correctly across scenarios took iteration, and clean URL routing via .htaccess was a fight on Hostinger's shared hosting. Packaging the system as an Android APK introduced mixed-content and viewport issues I hadn't planned for, and refining the UI across every breakpoint — modals, sidebars, hamburger menus — was long but necessary.

On the research side, wording the Patient Satisfaction Questionnaires to stay valid and unbiased on a 4-point Likert scale, then tying the data and system performance into coherent conclusions under Mondriaan Aura College's APA format, took as much care as the code.

Outcomes

The system shipped to production at gavinadental.online — a real, working platform the clinic uses to manage appointments, records, treatment plans, inventory, and communications in one place, with patients able to register and book online. The Android APK extended that reach as a native-feeling app without a separate codebase.

Leading 4 developers through it — architecture decisions, code review, keeping the team aligned on conventions — was real technical leadership experience I later carried into DevBoard. The pre/post-test satisfaction data validated the system's effectiveness, and the project earned the Best in Project Implementation award at my Capstone/Thesis defense — proof this wasn't just a school assignment but a fully deployed, award-winning system I built and led.
