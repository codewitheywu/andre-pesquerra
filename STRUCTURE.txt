PORTFOLIO — FOLDER STRUCTURE
════════════════════════════════════════════════════════

Place the entire `portfolio/` folder inside your web server's
document root, e.g. for WAMP:
  C:\wamp64\www\portfolio\

The app auto-detects its own URL and subfolder from the request
(see includes/url.php) — no hardcoded paths to edit, whether it's
served from a subfolder or a domain root.

────────────────────────────────────────────────────────
portfolio/
│
├── index.php                     ← Main portfolio page (entry point)
├── robots.txt                    ← Disallows /cms/ and /includes/
├── .htaccess                     ← Directory-listing off, blocks .sql/.md/.log
│
├── includes/
│   ├── db.php                    ← PDO connection, DB env vars, error-display bootstrap
│   ├── data.php                  ← All DB query functions
│   ├── url.php                   ← Host-agnostic URL helpers (siteBaseUrl, urlPathFor)
│   ├── security.php              ← sendSecurityHeaders() — CSP, X-Frame-Options, etc.
│   └── .htaccess                 ← Blocks direct HTTP access to this folder
│
├── pages/
│   ├── contact_handler.php       ← AJAX contact form endpoint (POST), rate-limited + honeypot
│   ├── project.php                ← Single project / case study page
│   └── sitemap.php               ← Dynamic sitemap.xml (all published projects)
│
├── assets/
│   ├── css/
│   │   ├── style.css             ← Full design system (tokens, layout, components, responsive)
│   │   └── project.css           ← Case-study page styles
│   ├── js/
│   │   └── main.js               ← Nav, reveals, skill bars, contact AJAX
│   ├── img/
│   │   ├── avatar/                ← Profile photo
│   │   ├── logos/                 ← Company / institution logos
│   │   ├── skills/                ← Skill icons
│   │   └── projects/, testimonials/, uploads/  ← CMS-uploaded images (auto-created)
│   └── files/                    ← CMS-uploaded documents (e.g. resume.pdf)
│
├── database/
│   ├── schema.sql                ← Full DB schema (structure only) — import to set up fresh
│   └── README.md                 ← Setup + deployment instructions, incl. creating the admin user
│
└── cms/                          ← Admin CMS
    ├── index.php                 ← Dashboard (stats, recent messages)
    ├── login.php                 ← Auth, with brute-force lockout

    │   ├── config.php            ← BASE_URL/PUBLIC_URL/UPLOAD_URL (auto-detected), upload + URL-safety helpers

════════════════════════════════════════════════════════
QUICK-START CHECKLIST
════════════════════════════════════════════════════════

1. Copy portfolio/ into your web server's document root.
2. Set up the database — see database/README.md for full steps:
   → Create an empty database, import database/schema.sql,
     then create your admin CMS account.
3. Local dev needs no configuration — includes/db.php falls back
   to DB_HOST=localhost / DB_USER=root / DB_PASS=(empty) automatically.
   Deploying elsewhere? Set DB_HOST / DB_NAME / DB_USER / DB_PASS /
   APP_ENV as real environment variables — no code edits needed.
4. Visit your site's URL (e.g. http://localhost/portfolio/) and
   log in to the CMS at /cms/login.php to manage your content.

════════════════════════════════════════════════════════
KNOWN LIMITATIONS
════════════════════════════════════════════════════════

- The per-IP contact-form rate limit uses REMOTE_ADDR directly; if
  ever deployed behind a reverse proxy/load balancer, every visitor
  would share one IP from the app's perspective, collapsing the cap
  into one shared quota for everyone. Not an issue on a direct host.
- CMS login lockout (cms_login_attempts) is IP-based — a determined
  attacker rotating IPs isn't stopped by it, only casual brute-forcing.
